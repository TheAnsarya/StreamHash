#### RIPEMD-256
- 256-bit output (32 bytes)
- 4 rounds × 16 steps = 64 operations
- Dual-line parallel structure with variable exchange (A, B, C, D in order)
- Little-endian byte order

#### RIPEMD-320
- 320-bit output (40 bytes)
- 5 rounds × 16 steps = 80 operations
- Dual-line parallel structure with variable exchange (B, D, A, C, E order!)
- Little-endian byte order
- **Bug Fixed**: Exchange order was wrong. Spec says B→D→A→C→E, not A→B→C→D→E

## Technical Notes

### RIPEMD Exchange Order Discovery

The RIPEMD-256 and RIPEMD-320 algorithms have different exchange orders despite similar structure:

| Algorithm | Round 0 | Round 1 | Round 2 | Round 3 | Round 4 |
|-----------|---------|---------|---------|---------|---------|
| RIPEMD-256 | A | B | C | D | - |
| RIPEMD-320 | B | D | A | C | E |

This was the root cause of RIPEMD-320 test failures.

### SM3 Initial Values

The spec shows values that must be interpreted carefully:
```
IV0 = 0x7380166f (correct)
IV3 = 0xda8a0600 (NOT 0xa96f37fe as some sources show)
```

### Performance Gains

The stackalloc optimization technique achieves **near-zero allocation** by:
- Using stack-allocated state arrays instead of heap-allocated class instances
- Only allocating the final result `byte[]` on the heap
- Eliminating GC pressure in hot paths
